## Proteção do ramo main (passo 5)

O ramo `main` tem regras de proteção activas (`Settings → Rules`) que exigem a
passagem de status checks antes do merge — confirmado na prática, por o push
directo para `main` ter sido recusado com `GH013: Repository rule violations found`.
O check `Checkstyle naming gate 129843` foi acrescentado à lista de checks
obrigatórios, ficando o botão de merge bloqueado enquanto o gate estiver vermelho.

## O que o Checkstyle não consegue verificar (passo 6)

O Checkstyle valida a **forma** do identificador, não o seu **significado**. Um
nome como `Xpto` ou `Dados1` cumpre integralmente a expressão regular do
`TypeName`, tal como `Position`, apesar de não comunicar nada sobre a
responsabilidade da classe. Do mesmo modo, nomes genéricos como `Manager`,
`Helper` ou `Util` passam a verificação sendo precisamente os que costumam
sinalizar classes sem uma responsabilidade clara. A adequação semântica de um
nome, a coerência do vocabulário usado ao longo do projeto e a correspondência
entre o nome e aquilo que a classe realmente faz continuam a exigir revisão
humana em code review.
