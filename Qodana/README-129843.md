Proteção do ramo main (passo 5)

O ramo main tem regras de proteção activas que exigem a passagem de status checks antes do merge. Isto foi confirmado na prática: uma tentativa de push directo para main foi recusada pelo servidor com

remote: error: GH013: Repository rule violations found for refs/heads/main.
remote: - 2 of 2 required status checks are expected.

Não foi possível acrescentar o check Checkstyle naming gate 129843 à lista de checks obrigatórios, por o ruleset pertencer ao proprietário do repositório e eu não dispor de permissões de administração sobre o mesmo (o separador Settings não está acessível na minha conta). Como consequência, o pull request com a violação pôde ser fechado apesar de o gate estar vermelho: o workflow sinaliza o problema, mas não impede por si só o merge. O guião prevê esta situação, indicando que a funcionalidade pode depender do tipo e do plano do repositório.

O que o Checkstyle não consegue verificar (passo 6)

O Checkstyle valida a forma do identificador, não o seu significado. Um nome como Xpto ou Dados1 cumpre integralmente a expressão regular do TypeName, tal como Position, apesar de não comunicar nada sobre a responsabilidade da classe. Do mesmo modo, nomes genéricos como Manager, Helper ou Util passam a verificação sendo precisamente os que costumam sinalizar classes sem uma responsabilidade clara. A adequação semântica de um nome, a coerência do vocabulário usado ao longo do projeto e a correspondência entre o nome e aquilo que a classe realmente faz continuam a exigir revisão humana em code review.
