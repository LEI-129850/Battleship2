# Checkstyle quality gate: convenção de nomes (BattleShip2)

Tipo de identificador escolhido: **métodos** (regra `MethodName`).
Convenção: nomes de métodos em *camelCase*, ou seja, começam por letra minúscula e não têm sublinhados nem espaços (Google Java Style Guide e convenções da Oracle). Expressão regular usada: `^[a-z][a-zA-Z0-9]*$`.

## Ficheiros desta entrega

| Ficheiro | Localização |
|---|---|
| Workflow | `.github/workflows/checkstyle-129850.yaml` |
| Configuração do Checkstyle | `checkstyle-129850.xml` |

A configuração contém apenas a regra de nomes (`MethodName`), com `severity` = `error`, sem as restantes regras das configurações da Google ou da Sun (indentação, Javadoc, etc.).

## Workflow

O workflow corre em cada *pull request* e usa a action `dbelyaev/action-checkstyle@v3` (Checkstyle 13.10.0 com reviewdog). O job chama-se `checkstyle-129850`. Com `fail_level: error` o workflow falha quando existem violações com severidade `error`. Por omissão, o reviewdog só reporta violações nas linhas adicionadas ou alteradas pelo pull request (`filter_mode: added`).

## Provocar a violação (passo 4)

Foi acrescentado, num ramo à parte, o método `Teste_Erro_Checkstyle` em `Game.java`, que viola a regra por ter letras maiúsculas e sublinhados fora do padrão camelCase. O workflow falhou e o Checkstyle indicou o ficheiro, a linha e a regra violada:

```
src/main/java/battleship/Game.java:591:21: error: Name 'Teste_Erro_Checkstyle' must match pattern '^[a-z][a-zA-Z0-9]*$'. (com.puppycrawl.tools.checkstyle.checks.naming.MethodNameCheck)
reviewdog: found at least one issue with severity greater than or equal to the given level: error
```

Depois de corrigir o nome do método, o workflow voltou a passar.

## Proteção do ramo `main` (passo 5)

O ruleset do `main` exige que dois checks do GitHub Actions passem antes do merge de um pull request: `qodana-129850` (tarefa 2A) e `checkstyle-129850` (tarefa 2B). Com a violação presente, o check `checkstyle-129850` fica a vermelho e o merge do pull request fica bloqueado.

## O que o Checkstyle não consegue verificar

O Checkstyle só valida a forma do nome contra uma expressão regular, por isso não sabe se o nome é significativo: um método chamado `x1()` ou `faz()` cumpre o padrão, mas não descreve o que faz. Também não verifica se o nome corresponde ao comportamento real do método, nem a coerência com o idioma do projeto.
